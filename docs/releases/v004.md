# TrackSwap v004

v004 聚焦于多路由压力测试后的恢复能力和目标选择安全性。

## 主要变化

- 物理来源暂时断开时，已启用的虚拟代理保持注册但上报无效位姿，避免 SteamVR 在同一会话中丢失静态绑定；来源恢复后可自动继续跟随。
- 阻止一条路由读取另一条路由已覆盖的设备角色，避免多个设备发生级联移动。
- 运行时目标选择改为明确的实体设备。旧的 SteamVR 角色目标配置会显示迁移提示，在改选实体设备前不能应用或启用。
- 点击“重新读取”后保留已配置但暂时离线的来源，不再把下拉框留空。
- 包含 v003 之后的交互式 3D 预览、OpenVR 设备模型加载、延迟删除和隐藏虚拟代理模型等改进。

## Pico 手柄兼容性提示

具体设备之间的 `TrackingOverrides` 属于实验性用法，是否生效取决于 SteamVR 版本和目标设备驱动。在本次硬件测试中：

- Valve Index Knuckles 作为明确的实体目标时可正常跟随。
- Pico 手柄作为明确的实体目标时，出现过覆盖被忽略或无法跟随的情况。

这是已观测到的兼容性限制，不代表所有 Pico 设备或驱动版本必然失败。使用 Pico 目标时，请先在 SteamVR 中目视确认跟随结果，并对照 TrackSwap 预览和状态；TrackSwap 不会在实体目标失败时静默切换到 SteamVR 角色目标。

## 验证摘要

- Windows x64 Release 构建、Protocol 测试、Runtime 测试和原生驱动位姿测试。
- 多路由独立跟随与局部偏移。
- 来源断开、重新连接与 Runtime/UI 稳定性。
- 明确实体目标的 Knuckles 硬件跟随。
